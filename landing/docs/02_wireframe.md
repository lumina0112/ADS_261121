# 02. 와이어프레임 사양 (제안)

2026-11-21 · 상태: **제안**, cize 검토 대기
확정된 전제: 첫 화면 B안(짠 데모), 구역 6개 구성 (`01_plan.md`)
파일: `wireframe/index.html` (주석 포함), `wireframe/index.html?clean` (주석 없음)
스크린샷: `wireframe/shots/` (1440px, 360px는 deviceScaleFactor 2)

---

## 0. 결론 요약

- 와이어프레임은 **실제 문구를 넣은 회색조 화면**입니다. 색과 그림만 비워 두었고, 격자와 글자 크기는 구현값을 그대로 썼습니다. 그래서 문구 길이와 줄바꿈을 이 단계에서 미리 검수할 수 있습니다.
- 화면은 구역 6개, 상호작용 요소 4종(짠 데모, 몸짓 재생, 잔 색 선택, 신청 폼)으로 이루어집니다.
- 신청 폼에는 **상태 여섯 가지**(빈 칸, 형식 오류, 동의 없음, 보내는 중, 전송 실패, 완료)와 개인정보 동의 항목을 넣었습니다.
- 측정 이벤트는 **일곱 가지**로 정했습니다. 신청률(form_success ÷ page_view)이 IR 실험 2의 핵심 지표입니다.
- 검수: 360, 390, 768, 1440px에서 가로 스크롤 없음, 마지막 줄이 첫 줄의 30% 미만인 문단 없음, 문구 검사 0건.

## 2. 구역별 사양

### 1. 첫 화면
- 격자: 1024px 이상 7:5, 그 아래는 한 열(문구 위, 데모 아래).
- 제목은 두 줄로 고정합니다(줄마다 `display:block`). 소개는 문장마다 줄을 나눕니다.
- 짠 데모
  - 처음 상태: 소리 없음. 칩 "내 곡", "친구 곡". 버튼 "짠".
  - 누른 뒤: 내 곡(왼쪽) → 친구 곡(오른쪽) → 잔이 부딪힘 → 섞인 곡(가운데), 약 4초. 버튼 "듣는 중", 다시 누를 수 없음.
  - 끝난 뒤: 칩 "한 곡으로 섞임". 버튼 "다시 짠".
  - 화면 낭독기: "내 곡과 친구 곡이 따로 있습니다." → "두 곡이 한 곡으로 섞였습니다."
  - 움직임 줄이기를 켠 사용자: 잔이 움직이지 않고 상태만 바뀝니다. 소리는 그대로 납니다.

### 2. 문제
- 확정 문장이므로 고치지 않습니다. 보충 문장 "그래서 친구와 모여도 음악은 함께 듣기만 합니다."는 제안입니다.

### 3. 쓰는 방법
- 제목: 혼자 들을 땐 스피커, 친구가 오면 합주가 됩니다
- 01 잔 하나 얹기 / 02 친구의 잔 더하기. 단계마다 그림 칸(16:10)을 둡니다.
- 768px 이하에서는 한 열로 쌓고 블록을 화면 끝까지 붙입니다.

### 4. 몸짓
- 카드 순서는 확정 표 순서(짠, 쌓기, 두드리기, 돌리기, 털기)입니다. 짠과 쌓기를 넓은 카드로 둡니다.
- 한 번에 한 카드만 재생합니다. 다른 카드를 누르면 앞 소리를 멈추고 새 소리를 냅니다.
- 재생 중인 카드는 먹색 바탕으로 바뀌고 버튼 이름이 "재생 중"이 됩니다.

### 5. 잔 모듈 (P1)
- 카드 전체를 모듈 색으로 채웁니다. 와이어프레임에서는 회색 카드에 테두리를 두어 자리만 표시했습니다.
- 들 카드는 바탕과 대비가 낮으므로 안쪽 테두리를 유지합니다(DESIGN.md 3장).

### 6. 구성과 알림 신청
- 왼쪽: 제목, 소개, 세트 구성 두 줄(P1).
- 오른쪽 폼
  1. 메일 주소(필수)
  2. 내 잔 색(선택, 라디오 다섯 개). 미리 고른 값 없이 시작합니다. 와이어프레임의 "노을" 선택은 선택 상태를 보여 주기 위한 예시입니다.
  3. 개인정보 수집·이용 동의(필수 체크) + "내용 보기" 펼침
  4. 알림 신청 버튼
- 메시지는 버튼 바로 아래에 한 번에 하나만 나타나며, 화면 낭독기가 읽도록 `aria-live`를 씁니다.

## 3. 신청 폼 상태와 문구

| 상태 | 조건 | 문구 | 초점 이동 |
| --- | --- | --- | --- |
| 빈 칸 | 메일 주소가 비어 있음 | 메일 주소를 입력해 주세요. | 메일 입력란 |
| 형식 오류 | 형식이 맞지 않음 | 메일 주소 형식을 다시 확인해 주세요. | 메일 입력란 |
| 동의 없음 | 동의 체크가 없음 | 개인정보 수집·이용에 동의해야 알림을 보낼 수 있습니다. | 동의 체크 상자 |
| 보내는 중 | 전송 요청 중 | (버튼) 신청하는 중 | 그대로 |
| 전송 실패 | 저장소 오류, 연결 끊김 | 신청을 보내지 못했습니다. 잠시 뒤에 다시 시도해 주세요. | 버튼 |
| 완료 | 저장 성공 | 신청을 받았습니다. 판매를 시작하면 이 주소로 알려 드립니다. | 완료 문장 |

- 검사 순서는 위에서 아래(빈 칸 → 형식 → 동의)이며, 오류가 여럿이면 가장 위의 오류만 보여 줍니다.
- 완료되면 폼 자리에 완료 문장만 남깁니다. P1의 "친구에게도 알리기" 버튼은 이 자리에 둡니다.

### 동의 펼침 내용
| 항목 | 문구 |
| --- | --- |
| 수집 항목 | 메일 주소, 고른 잔 색 |
| 이용 목적 | KKAL 출시 소식 안내 |
| 보유 기간 | 출시 안내를 보낸 뒤 바로 파기 (**cize 확인 필요**) |
| 거부할 권리 | 동의하지 않을 수 있으며, 이 경우 출시 알림을 받을 수 없습니다. |

## 6. 구현 단계로 넘기는 과제

- **문제 문장의 모바일 줄바꿈**: 360px에서 "장비를 / 배운"으로 명사구가 갈라집니다. 확정 문장이므로 문구를 바꾸지 않고, 구현할 때 구절 단위 묶음(`white-space: nowrap`을 준 span)으로 "장비를 배운"을 한 덩어리로 묶습니다.
- **잔 모듈 카드의 2열 줄바꿈**: 모바일 2열에서 "낮게 받쳐 / 주는 소리"처럼 보조 용언이 갈라집니다. 카드 글자 크기를 14px로 낮추거나 "받쳐 주는"을 묶습니다.
- **그림 칸**: 첫 화면, 쓰는 방법 두 칸, 잔 모듈 다섯 칸, 세트 두 칸. 시안에서는 목업의 평면 SVG를 쓰고, 실물 렌더가 나오면 같은 칸에 넣습니다.

- "들을 땐"은 "들을 때는"의 준말입니다. 제목에서는 입말에 가까운 준말이 자연스럽고, 본문에서는 "때는"을 씁니다.
- "수집·이용"의 가운뎃점은 짝을 이루는 말을 묶는 용법이며 한 문장에 한 번만 씁니다(W-TYP-06).

### B. cize 확인이 필요한 것
1. 보유 기간: "출시 안내 후 바로 파기"로 둘지, 특정 날짜로 둘지
2. 잔 색 선택을 P1에서 P0으로 올릴지. 비용이 낮고 IR에서 쓸 수요 데이터를 줍니다.
3. 저장소와 측정 도구. 가장 가볍게 시작한다면 폼 서비스 하나와 방문 측정 도구 하나로 충분합니다.
