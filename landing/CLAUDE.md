# CLAUDE.md: KKAL B안 랜딩 페이지

이 저장소는 KKAL B안(창업 디벨롭 방향)의 랜딩 페이지를 구현하는 곳입니다. 작업을 시작하기 전에 이 문서, `DESIGN.md`, `WRITING_RULES.md`를 이 순서로 읽습니다. 세 문서가 서로 다르면 사용자(cize)가 이 대화에서 한 말, `CLAUDE.md`, `DESIGN.md`, `WRITING_RULES.md` 순서로 따릅니다.

## 1. 지금 할 일

- B안 랜딩 페이지를 구현합니다. 목표 고객은 음악을 좋아하지만 만들어 본 적 없는 20대이고, IR 심사위원도 이 페이지를 봅니다.
- 핵심 전환은 출시 알림 신청(메일 주소 입력)입니다. 신청을 저장할 백엔드는 아직 정하지 않았습니다(8. 미정 사항).
- 디자인 시스템은 `DESIGN.md`(Clay와 Figma DESIGN.md를 KKAL 색으로 고친 변형본)를 따릅니다.
- `_draft/index.html`은 cize가 "시안 제작 전에 정리만" 하라고 하기 전에 만들던 초안입니다. 구조와 그림 함수를 참고할 수는 있지만, cize가 검토하지 않았으므로 그대로 쓰지 않습니다.

## 2. 작업 원칙

프로젝트 지식 파일 00에 적힌 원칙과 cize가 대화에서 정한 방식입니다.

- **근거 우선**: 근거가 없는 수치를 만들지 않습니다. 가격, 출시일, 사양(배터리, 연결 방식, 크기), 판매량, 사용자 수는 cize가 준 값만 씁니다. 빈칸은 추측으로 채우지 않고 그 요소를 뺍니다.
- **제안과 결정 구분**: cize가 확정하지 않은 내용은 "제안"으로 표시합니다. 이 문서 4장의 확정 항목만 사실로 다룹니다.
- **확정 사항 보호**: 지식 파일 04의 확정 사항(모듈 색, 몸짓 등)을 덮어쓰지 않습니다.
- **덜어내기**: 화면과 문장을 채우려고 요소를 늘리지 않습니다.
- **시각물 검수**: 화면을 바꾸면 스크린샷을 찍어 직접 확인한 뒤 보고합니다(7. 검수 절차).
- **모호하면 질문 하나**: 해석이 갈리면 가장 그럴듯한 해석으로 진행하되, 꼭 필요한 질문은 하나로 줄여서 묻습니다.
- **보고 형식**: 개조식, 두괄식. 결론 요약을 먼저 쓰고 부연 설명은 뒤에 씁니다.
- **언어**: 대화와 화면 문구는 한국어입니다. 코드, 변수명, 커밋 메시지는 영어로 씁니다.
- **역할 기대**: UX/UI, 제품, 그래픽 디자인의 관점과 인류학·사회학 관점의 통찰을 함께 냅니다.

## 3. 제품 정의(확정)

- KKAL은 **기본적으로 스피커**입니다. 바디 모듈(스피커)과 한 사람당 하나씩 갖는 잔 모듈로 이루어진 **소셜라이징 모듈형 제품**이며, 이 정체성은 반드시 유지합니다.
- 혼자 쓸 때: 바디 모듈에 잔 모듈을 얹으면 그 잔의 성질에 맞춰 소리가 튜닝됩니다.
- 함께 쓸 때: 친구가 자기 잔을 가져와서 다섯 가지 몸짓으로 함께 음악을 바꿉니다.
- 술자리는 강한 소셜 인터랙션을 빌려 온 **모티프**일 뿐입니다. 술자리용 도구로 소개하지 않고, 화면 문구에 술자리, 술상, 주점, 건배 같은 말을 쓰지 않습니다. 술자리 이야기는 발표에서 몸짓의 출처로만 꺼냅니다.

### 문제와 제안 가치
- 문제 정의(확정): "음악은 누구나 듣지만, 섞고 바꿔 보는 일은 장비를 배운 소수의 몫입니다." 공모전에도 쓸 수 있는 문장으로 유지합니다.
- 제안 가치(확정 뉘앙스): 음악에 관심 있는 초보자도 친구와 함께 믹싱과 튜닝을 손쉽게 해 볼 수 있습니다.

### 고객(확정, 2026-11-21)
- 핵심: 음악을 좋아하지만 만들어 본 적 없는 20대. 혼자서는 시작하지 않아도 친구와 함께라면 해 보는 사람.
- 확장: 10대 후반(선물, 음악 창작 수업), 30대(집 모임, 선물).
- 제외: 주점, 포차 같은 B2B 구매자.

### 사업 구조(IR 문서의 제안, cize 검토 대기)
- 수익: 기본 세트(바디 모듈 하나와 잔 모듈 둘) + 추가 잔 모듈. 추가 잔은 친구가 사서 합류하므로 재구매이자 신규 고객입니다.
- 진입: 대학 음악 동아리와 교내 행사 체험 부스, 크라우드펀딩 선판매. 동아리 부원은 핵심 고객보다 소개자에 가깝습니다.
- 초기 근거: UT 5쌍 10명. 짠은 5쌍 모두 안내만으로 수행했고, 10명 중 9명이 상대 취향을 더 잘 알게 되었다고 답했습니다(평균 1.6 → 2.4).
- 빈칸: 가격, 원가, 시장 규모, 실재성 근거(심층 인터뷰 10명 이상). cize가 초기 설문, 심층 인터뷰, FGI 자료를 찾는 중입니다.

### 경쟁과 선례(조사 완료)
- 같은 제품은 국내외에 없습니다. 가장 가까운 선례는 DropMix(2017, NFC 카드와 보드, 2022년 앱 종료)와 Fuser(2022년 종료)입니다.
- 교훈: 앱이 멈추면 제품도 멈췄습니다. KKAL은 앱 없이도 스피커로 남는 설계를 차별점으로 내세웁니다(제안).
- 사업 구조의 근거: Tonies(피규어가 매출의 약 71%), 국내 구조가 가장 가까운 곳은 키트앨범.
- 수치는 조사 문서의 출처 범위 안에서만 인용합니다.

## 5. 금지 사항

### 시각
- 난색 미색(베이지, 아이보리, 크림, #F7F3F0 같은 누런 흰색). cize가 "Claude 작업물이 연상되는 색"이라고 금지하였습니다. Clay 원본의 크림 바탕도 쓰지 않습니다.
- 생화이트 #FFFFFF, 생블랙 #000000, 검정과 형광 라임 조합.
- 그림자, 장식용 그라데이션, 보라색 계열 UI 색(밤은 모듈 카드에만 씀), 이모지.
- 줄마다 반복되는 얇은 구분선. 구역은 여백과 색 면으로 나눕니다.
- 회색 본문 글자. Muted 색은 캡션에만 씁니다.
- 고정폭 대문자 라벨(생성형 화면에서 흔한 모양).
- 화면 사용법을 설명하는 안내 문장, 점수 설명, 단계 수나 이미지 수 같은 메타 표기.

### 문구
- 술자리, 술상, 주점, 건배 같은 말.
- "색 = 악기"를 앞세운 설명.
- 확정되지 않은 가격, 출시일, 사양.
- `WRITING_RULES.md`의 금지어와 금지 구조(번역체, "~가 아니라 ~", 홍보 문구, em dash 등).

## 6. 랜딩 페이지 구현 브리프(제안)

### 구역 구성(위에서 아래로)
| 메뉴 | 구역 | 내용 | 표현 |
| --- | --- | --- | --- |
| | 첫 화면 | 라벨 "Social modular speaker", 제목, 소개 문단, 버튼 둘(출시 알림 받기, 몸짓 들어 보기) | 흰 바탕 7:5. 오른쪽 그림 칸에 바디 모듈과 잔 모듈 |
| | 문제 | 문제 정의 문장과 한 줄 보충 | 큰 글자 |
| How | 쓰는 방법 | 01 바디 모듈 켜기, 02 잔 모듈 얹기, 03 친구의 잔 더하기 | 숲 색 블록 |
| Gestures | 몸짓 | 다섯 몸짓 카드와 소리 데모 | 연한 면 카드. 짠과 쌓기는 넓은 카드 |
| Modules | 잔 모듈 | 다섯 색 카드 | 모듈 색 카드(Clay식) |
| | 혼자와 함께 | 혼자 쓸 때, 함께 쓸 때 | 먹색 블록, 두 칸 |
| Set | 구성 | 기본 세트, 추가 잔 모듈 | 흰 바탕 카드 두 장 |
| | 알림 신청 | 제목, 메일 입력, 버튼 | 들 색 블록 |

- 메뉴 이름은 영어(How, Gestures, Modules, Set)로 씁니다(WRITING_RULES CONFIG).
- 몸짓 카드에는 모듈 색을 칠하지 않습니다. 몸짓과 모듈이 짝인 것처럼 읽히기 때문입니다. 색 하나에는 의미를 하나만 줍니다.
- 한 화면에 색 블록은 하나만 보이게 하고, 색 블록 사이에는 흰 바탕을 둡니다.

### 카피 초안
- 제목: 잔을 부딪치면, 음악이 섞입니다
- 소개: KKAL은 바디 모듈과 잔 모듈로 이루어진 스피커입니다. 음악을 만들어 본 적 없어도 짠, 쌓기, 두드리기 같은 몸짓으로 친구와 함께 음악을 바꿀 수 있습니다.
- 문제 보충: 그래서 친구와 모여도 음악은 함께 듣기만 합니다.
- How 제목: 스피커로 켜고, 잔을 얹어 바꿉니다
  - 바디 모듈 켜기: 평소에 듣던 음악을 바디 모듈로 틉니다.
  - 잔 모듈 얹기: 잔을 바디 모듈 위에 올리면 그 잔의 성질에 맞춰 소리가 튜닝됩니다.
  - 친구의 잔 더하기: 친구가 자기 잔을 가져오면 다섯 가지 몸짓으로 함께 음악을 바꿉니다.
- Gestures 제목: 다섯 가지 몸짓이 DJ 기술을 대신합니다(카드 문구는 3장의 몸짓 표)
- Modules 제목: 잔은 다섯 가지입니다
  - 소개: 잔마다 맡는 소리가 달라서, 어떤 잔이 모이느냐에 따라 같은 노래도 다르게 들립니다.
  - 숲 낮게 받쳐 주는 소리, 밤 겹겹이 쌓이는 화음, 노을 앞에 나서는 멜로디, 여울 잘게 튀는 타악기, 들 넓게 깔리는 배경음
- 혼자와 함께 제목: 잔이 하나면 스피커, 여럿이면 합주가 됩니다
  - 혼자 쓸 때: 바디 모듈에 잔 하나를 얹어 둡니다. 잔을 바꿔 얹으면 같은 노래가 다른 분위기로 튜닝됩니다.
  - 함께 쓸 때: 친구마다 자기 잔을 하나씩 가져옵니다. 잔이 늘어날수록 섞을 수 있는 소리도 늘어납니다.
- Set 제목: 기본 세트로 시작하고, 친구가 잔을 더합니다
  - 기본 세트: 바디 모듈 하나와 잔 모듈 둘
  - 추가 잔 모듈: 다섯 색 가운데 하나를 골라 자기 잔으로 씁니다.
- 알림 신청 제목: 출시 소식을 먼저 받아 보세요
  - 소개: 판매를 시작하면 메일로 알려 드립니다.
  - 완료: 신청을 받았습니다. 판매를 시작하면 이 주소로 알려 드립니다.
  - 오류: 메일 주소 형식을 다시 확인해 주세요.

### 기술 권장
- 정적 페이지로 시작합니다. 프레임워크가 필요하면 Astro나 Vite를 쓰고, 구성 요소가 늘어나기 전에는 순수 HTML, CSS, JS로 충분합니다.
- 글꼴: Pretendard Variable(`pretendard@1.3.9`, jsDelivr 또는 직접 호스팅), Unbounded(Google Fonts, OFL).
- 색, 글자, 간격, 모서리는 `DESIGN.md` front matter의 값을 CSS 변수로 옮겨 씁니다. 화면 코드에 색 값을 직접 쓰지 않습니다.
- 몸짓 소리 데모: 시안은 Web Audio 합성음입니다. 실제 음원(스템)을 쓰게 되면 Tone.js로 옮깁니다. 소리는 사용자가 버튼을 눌렀을 때만 냅니다.
- 그림: 실물 모듈 렌더가 없으므로 평면 SVG로 자리를 잡고, 렌더가 나오면 같은 칸에 넣습니다. Clay처럼 3D 렌더가 들어갈 자리입니다.
- 한글 줄바꿈: `word-break: keep-all`, `text-wrap: pretty`, 그리고 `WRITING_RULES.md` W-TYP-07, 08의 `tie()`와 `commaBreak()`를 그대로 씁니다.
- 접근성: 버튼과 입력창 높이 44px 이상, 키보드 초점 표시, `prefers-reduced-motion`이면 모든 움직임을 끕니다. 색 대비는 `DESIGN.md` 3장 표를 따릅니다.

## 7. 검수 절차

1. `python3 tools/lint_writing.py <파일>`로 화면 문구를 검사해 error 0을 확인합니다. warn 성격의 결과는 한 줄씩 읽고 판단합니다.
2. Playwright로 360px, 390px, 768px, 1440px 폭에서 스크린샷을 찍어 직접 봅니다. 가로 스크롤, 한 글자 줄끝(W-TYP-07), 쉼표 뒤 한 단어 줄끝(W-TYP-08), 마지막 줄 길이(W-TYP-09)를 확인합니다.
3. cize에게 보이는 스크린샷은 deviceScaleFactor 2로 찍습니다.
4. 보고는 개조식, 두괄식으로 하고, 바꾼 점과 확인하지 못한 점을 나눠 적습니다.
